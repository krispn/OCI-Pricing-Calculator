# OCI Pricing Calculator — Project Summary

## Overview

A browser-based Oracle Cloud Infrastructure pricing calculator. Users build cost estimates across multiple OCI services using live pricing data fetched from Oracle's public APIs. No backend server required — it runs as a static site served by any web server (Nginx, Python http.server, etc.).

**Tech stack:** Vanilla JavaScript, AG Grid Community 31.3.2, SheetJS (XLSX), SparkMD5, HTML/CSS.

---

## Architecture

```
index.html                    Main page — header, tabs, summary
css/styles.css                All styling
js/
  sku-catalog.js              SKU part numbers, service IDs, constants
  pricing-service.js          Loads/caches pricing data, exposes getPrice()
  compute-grid.js             Compute tab (VMs, shapes, OS, storage)
  object-storage-grid.js      Object Storage tab (Standard/IA/Archive)
  file-storage-grid.js        File Storage tab
  database-grid.js            Base Database tab (OCPU/ECPU editions)
  exadata-grid.js             Exadata Exascale tab
  autonomous-db-grid.js       Autonomous Database tab
  network-grid.js             Network tab (LB, NLB, FastConnect)
  export-service.js           Excel, Oracle format, save/load estimates
  app.js                      Bootstrap, tab nav, summary, global controls
data/
  pricing-snapshot.json        Pre-fetched pricing data (generated by update script)
deploy/
  setup-oci-vm.sh             One-command deployment to OCI free-tier VM
```

### Module Pattern

Every grid module is an IIFE returning public methods:

```js
const SomeGrid = (() => {
    let gridApi, onTotalsChanged;
    // private functions: createDefaultRow, calculateRowCost, recalcAll, updateTotals, ...
    return { init, recalcAll, getGridApi, getAllData, loadData, getMonthlyTotal, ... };
})();
```

### Data Flow

1. User edits a cell -> AG Grid fires `onCellValueChanged`
2. Grid recalculates that row's cost via `PricingService.getPrice(sku)`
3. Grid calls `updateTotals()` -> fires `onTotalsChanged` callback
4. `app.js` `updateSummary()` aggregates all grids -> updates header running total, summary table, bar chart, annual projection

### Script Load Order (matters)

```
sku-catalog.js -> pricing-service.js -> [all grid modules] -> export-service.js -> app.js
```

## Pricing Data

### Source

Two Oracle public APIs:
- **Products API:** `https://apexapps.oracle.com/pls/apex/cetools/api/v1/products/?currencyCode=USD`
- **Shapes API:** `https://www.oracle.com/a/ocom/docs/cloudestimator2/data/shapes.json`

### Update Flow

1. Run `update-prices.sh` (or `.bat` on Windows)
2. Script fetches both APIs, runs inline Python to merge into `data/pricing-snapshot.json`
3. Snapshot contains: `{ timestamp, fetchedAt, prices, shapes, buildId }`
4. `buildId` is preserved from shapes.json for Oracle Cost Estimator export compatibility

### Caching

- Primary: `data/pricing-snapshot.json` (file)
- Secondary: `localStorage` (7-day TTL)
- Fallback: Stale localStorage cache if file fetch fails (status badge turns red)

## Key Features & How They Work

### Compute Grid

- **Shapes:** Loaded dynamically from pricing snapshot; supports Flex (user sets OCPUs/memory) and Fixed shapes
- **GPU shapes:** Detected via `presetNames.includes('OCI_COMPUTE_GPU')`; price is per-shape, not per-OCPU
- **OS options:** Loaded per-shape from `supportedOSImages`; "Oracle Linux" is injected if any linux type exists
- **Windows licensing:** Added as separate cost via B88318 SKU (`$0.092/OCPU/hr`)
- **Storage:** Boot volume + Block volume with configurable VPU performance tiers (0-120)
- **Capacity types:** On-Demand, Preemptible, Reserved 1Y (42% discount), Reserved 3Y (60% discount)
- **FSDR:** Per-OCPU/hr charge in primary region when enabled

### FSDR (Full Stack Disaster Recovery)

FSDR costs are handled specially to match Oracle's presentation:

- Each grid with FSDR support (Compute, Base DB, Autonomous DB) exposes `getFsdrMonthly()`
- `app.js` subtracts FSDR from each grid's total and shows it as a separate "FSDR" summary line
- Databases charge 2x CPUs (primary + standby); Compute charges 1x (primary only)
- FSDR OCPU and ECPU have different SKUs

### DR Storage

- When FSDR is enabled, boot/block volumes are replicated to standby region
- DR storage uses Lower Cost (0 VPU) tier — no performance unit charge
- Aggregated across Compute, Base DB, Autonomous DB via `getDrStorageMonthly()`

### Object Storage Backup Row

- Auto-created row: "Backup (Default - 3x Boot+Block Volume)"
- Size = 3 x total compute boot+block volume (across all compute rows, qty-aware)
- Updates automatically when compute storage changes
- Deferred via `setTimeout(..., 0)` to avoid AG Grid re-entrant render errors
- Tracked via `_isBackupDefault: true` flag on the row data

### Pinned Totals Rows

Each grid has a pinned bottom row showing aggregated totals:

| Grid | Totals Shown |
|------|-------------|
| Compute | Server count, OCPUs, Memory, Boot Vol, Block Vol, FSDR count |
| Object Storage | Total Size, Total Retrieval |
| File Storage | Total Size |
| Base DB | DB count, OCPUs/ECPUs breakdown, Storage |
| Exadata | Total ECPUs, VMs, VM FS, Smart DB, Flash Cache |
| Autonomous DB | Total ECPUs, Total Storage |

Styled with `#e8f0fe` background. Editing is blocked via `onCellEditingStarted` check.

### Summary Tab

- Category breakdown table with percentage of total
- Horizontal bar chart
- Running total in header (formatted with comma separators)
- **Annual projection table:** Configurable discount % and number of years; shows monthly, annual, cumulative per year; green savings row when discount > 0

## Export Formats

### Excel (`exportToExcel`)
- Multi-sheet XLSX: one sheet per grid tab + Summary + Info
- Currency columns formatted as `$#,##0.00`
- Filename: `oci-estimate-YYYY-MM-DD.xlsx`

### Oracle Cost Estimator (`exportToOracleFormat`)
- JSON matching Oracle's import format for cross-validation at oracle.com/cloud/costestimator.html
- Hash: `SparkMD5.hash(JSON.stringify(configs))` — Oracle validates on import
- `dataBuildID` from pricing snapshot's `buildId`

**Key format requirements learned from reverse-engineering:**

| Requirement | Detail |
|-------------|--------|
| Windows licensing | Must be a separate service (`id: 827`, "Compute - OS Images") linked via `serviceRef`, NOT an item in the compute service |
| `monthlyCost` | Round to 2 decimal places |
| All SKUs present | Services like Base DB, Autonomous DB, Exadata must include ALL possible edition SKUs with `qty: 0` for unselected |
| `utilization.instances` | Must reflect quantity for all service types |
| `presetID` | File Storage uses `null` with `addBySearch: true`; Block Volumes use `74`; Object Storage uses `61` |
| Service IDs | Compute VM: 822, OS Images: 827, Block Volumes: 881, Object Storage: 882, File Storage: 862, Base DB: 1101, etc. (full list in `sku-catalog.js`) |

### Save/Load Estimate
- JSON format, version 3: `{ version, timestamp, hoursPerMonth, compute, objectStorage, fileStorage, database, exadata, autonomousDb, network }`
- Filename: `oci-estimate-YYYY-MM-DD.json`

## Deployment (OCI Free Tier VM)

**Script:** `deploy/setup-oci-vm.sh`

**Target:** VM.Standard.A1.Flex (Ampere, Always Free — 4 OCPU, 24 GB) or VM.Standard.E2.1.Micro

**What it does:**
1. Installs Nginx, Python 3, Git, cron
2. Clones repo to `/var/www/oci-calculator`
3. Configures Nginx (static files, caching headers, no-cache for JSON/HTML)
4. Removes default Nginx site (`sites-enabled/default`)
5. Opens firewall (firewalld or iptables — inserts rule BEFORE reject-all)
6. Sets up cron: `git pull` every 15 min, `update-prices.sh` daily at 2 AM UTC

**OCI Console prerequisites:**
- Security List ingress rule for TCP port 80 (source `0.0.0.0/0`)

**Known gotchas:**
- Ubuntu OCI images have iptables REJECT rule that blocks port 80; script handles this by inserting ACCEPT before REJECT
- Must remove `/etc/nginx/sites-enabled/default` on Ubuntu (not just `conf.d/default.conf`)

## Common Tasks

### Adding a new OCI service

1. Add SKU entries to `js/sku-catalog.js`
2. Create `js/new-service-grid.js` following the module pattern (copy an existing grid)
3. Add tab button and pane to `index.html`
4. Initialize in `app.js`: `NewServiceGrid.init('container-id', updateSummary)`
5. Add to `updateSummary()` category list
6. Add to `export-service.js`: build functions for Excel, Oracle format, save/load
7. Add `<script>` tag to `index.html` (before `export-service.js`)

### Updating pricing data

```bash
bash update-prices.sh    # Fetches from Oracle APIs, builds snapshot
```

### Changing cost calculation logic

Each grid's `calculateRowCost(data)` function contains all pricing logic for that service type. Modify there and ensure `recalcAll()` propagates changes.

### Debugging Oracle export mismatches

1. Export from our tool
2. Import into Oracle Cost Estimator
3. Export from Oracle
4. Diff the two JSON files
5. Common issues: missing SKUs (Oracle expects all), wrong service IDs, `monthlyCost` precision, Windows as separate service
